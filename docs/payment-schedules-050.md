# 変動額の定期支出・借入予定表 0.5.0

2026-09-28。Node.js / SQLite版の追加機能。過去Excelの265件移行とは独立しており、口座の残高基準日方式は変更しない。

## 操作

設定 →「変動額の定期支出・借入予定表」から一覧、作成、詳細へ進む。種類はその他・借入・リース・分割払い・保険。名称、支払口座、取引先、休日調整を共通情報として登録する。

- 通常は年を含む日付＋金額の2列、借入は日付＋元本＋利息の3列をExcelからタブ区切りで貼り付ける。見出しは除く。整数円、カンマ区切りを許容し、数式や曖昧な年なし日付は拒否。
- 毎月末／毎月指定日で日付を生成し、金額のみ（借入は元本＋利息）を未入力行へ貼り付けることもできる。1予定表1000回以内。追加・保存前の行削除に対応。
- 借入の合計は元本＋利息。通常の引落方式は合算／別引落。各回は必要なときだけ例外を選ぶ。
- 日付の名目日と休日調整後の日を保存する。既存の銀行休業日処理を共用し、月末丸め、翌／前営業日、年越しに対応。
- 設定済み最終行で生成終了。予定表へ行を追加して延長する。継続固定支出とは別機能で、無期限の金額推測生成はしない。
- 保存済み行は詳細から「残予定を取消」。実績は残す。予定表のアーカイブは編集を閉じるだけで、未払予定の取消にはならない。

## データと計算

共通情報 `payment_schedules` → 各回 `payment_schedule_occurrences` → 銀行明細リンク `payment_schedule_legs` の3段階。銀行明細そのものは既存 `cashflow_transactions` の `source=payment_schedule` として保持する。

共通情報は名称、種類、口座、取引先、defaultDebitMode、holidayRule、メモ、archivedAt、versionと作成更新日時。借入は `principalStartMode(new/existing), originalPrincipal, loanDate, principalBalanceDate, principalOpeningBalance` を保持する。新規借入では当初額・実行日が必須。基準日は終了時点で、実行日以降。新規借入の開始時も基準日とその日の終了残元本を明示する。同日返済がないなら当初借入額を開始残元本とする。借入金の入金を自動計上しない。

各回は共通情報のスナップショット、名目日・調整後日、予定額または元本・利息、例外方式、解決済み方式、revision、version、取消日時を持つ。親を変えても既存回へ暗黙に適用しない。チェック指定された場合だけ、将来かつ全明細未実績かつ例外なしの回へ反映する。

銀行リンクは回ID、revision、component(total/principal/interest)、一意なtransactionId、actualPrincipal、actualInterestを保持。合算は銀行明細1件、別引落は正額の元本・利息を各1件。0円側の架空明細は生成しない。銀行明細IDは回ID＋revision＋componentのSHA-256から固定生成し、既存IDとの衝突は上書きせず拒否する。

銀行残高は既存計算を使い、確定した銀行明細のactualAmountを一度だけ計上する。残元本は基準残元本から基準日翌日以降・集計日以前のactualPrincipalだけを減算。基準日前は計算不能表示。実績利息はactualInterestとして別に保持し、予定元本・予定利息で実績集計を動かさない。計算が負になっても勝手に0補正しない。

## 実績・変更保護

各銀行明細を別々に実績化できる。元本だけ完了なら一部支払、両方完了なら支払済。合算は実績元本＋実績利息を入力して合計1件を確定する。実績との差額を勝手に利息や元本へ配賦しない。

確定済み銀行明細は一般取引APIからも編集・削除できない。実績がある回は予定表一括編集から保護。片方のみ実績化した別引落では、もう片方が将来の未実績である場合、その銀行明細の日付・額だけを個別編集できる。全実績の削除や上書き、実績登録後の借入基準の変更は拒否する。

変更は親versionを照合したSQLiteトランザクションで実行。全額の再送はrequestIdと要求ハッシュで一度だけ適用し、異なる内容で同じrequestIdを再利用すると拒否。回の全体編集では旧未実績明細を取消として残してrevisionを増やす。履歴・確定実績を物理削除しない。

## 日繰り・Excel・既存機能

日繰り・任意年月・期間Excelは既存銀行明細を使用し、合算1件／別引落2件を表示する。日繰りの明細から予定表の詳細と実績確定へ進む。予定表専用Excelでは予定・実績の元本／利息／合計、実績日、状態、関連IDを出力する。途中で別引落の支払日を個別変更した場合は、個別日付が日繰りに反映され、回の名目日・調整後日は元のまま残る。

既存固定支出・買掛・手動予定と自動照合・統合しない。同じ支払を別機能にも登録すると重複するため保存前に確認を表示する。既存固定支出の生成ID・仕組みは変更しない。

## DB更新と復旧

schema2→3では取引のsource制約を拡張するため取引表を再構築し、既存行・ID・索引・参照を維持して上記3表を追加。BEGIN IMMEDIATE、外部キー検証後にcommit。失敗時rollbackし外部キーを再有効化。schema1→2→3にも対応。既存管理者、口座、残高、取引を初期化しない。

旧0.4.0はschema3を読めないため、コードだけの巻き戻しは禁止。0.4.0へ戻す場合は更新前の整合バックアップを別の空DBへ旧版で復元し、入力停止・更新後データを退避したうえで切替する。更新後に追加したデータは旧DBに含まれないため、自動破棄せず差分を確認する。新版はschema1/2バックアップを空の復元先で3へ更新できる。元バックアップは変更しない。復元時はセッション・試行制限のみ消去し、管理者を維持する。
