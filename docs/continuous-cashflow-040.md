# 日付連続管理の拡張（0.4.0）

年度更新・年度別DB・年度締めは追加しない。SQLiteスキーマv2を維持し、既存のnullable endMonthのNULLを継続として扱う。管理者・口座・実績を移行・リセットしない。

固定支出は起動時と日本時間の日付変更後（毎分の確認）に、不足する過去分と当月～12か月先の対象月を補充する。開始月より前、終了月より後には生成しない。同じマスタ・対象月のIDを主キーとし、実績・取消を含む保存済み明細を優先。失敗はロールバックし、settingsのfixedExpenseMaintenance、画面、healthへ反映して次の確認で再試行する。履歴は削除しない。遠い将来は表示時に計算し、途中月の支出も残高へ含める。休日調整で月を戻る場合に備え指定期間の翌対象月まで評価する。GETとExcel出力は保存しない。

マスタ変更前に旧条件で不足を補充し、既存の変更範囲（今後／全期間）で未確定予定を再生成。確定実績と取消は保護する。終了したマスタの履歴を残すには終了月を設定する。実体化期間外の個別取消・確定はマスタ更新版を検証し、生成と操作を同一トランザクションで行う。

年月直接入力・前月・翌月・今月へを追加し、7か月タブを維持。期間Excelは最大60か月、期間集計と月別シート。表示モード・口座選択を引継ぎ、同一取得時点のデータで出力する。共通CashflowMathで日繰り・ホーム・Excelの残高を計算。過去予測は従来どおり現在状態から再計算し、固定保存ではない。

銀行営業日は土日・日本の祝日・12月31日・1月2日・1月3日を除く。1月1日は従来の祝日判定を利用。既存の祝日計算範囲・将来の法改正対応は従来どおり。

検証：年越し専用テストは固定時計・一時SQLiteを使用し、残高連続、分割決済、継続／有限予定、銀行休業日、過去／遠未来表示、無書込、補充、再起動回復、重複防止、実績・取消保護、実xlsxの読み戻し、バックアップ復元を確認する。
