# 口座管理変更・検証記録（2026-09-25）

アプリ0.3.0／SQLite v2をwf-productionの資金繰り専用app・backupへ反映済み。両コンテナはhealthy。

## 変更

- 旧「口座名」を入力欄・API・DBから廃止。銀行名を必須にし、支店名と口座番号を追加。
- `bank`、`branch`、`type`、`accountNumber`を独立保存。口座番号はSQLite TEXT／API文字列／画面テキスト入力。先頭0を保持し、数値型によるAPI入力は拒否する。
- 一覧・日繰り・売掛／買掛・入出金・固定支出・口座選択・Excelの口座表示を「銀行名 支店名」に統一。支店名が空なら銀行名だけを表示。口座番号は編集画面で確認でき、一覧やExcelに常時表示しない。
- 種別、基準日の終了残高、残高基準日の仕様・計算は維持。
- 旧DBは一度だけ移行し、銀行名が空の場合だけ旧口座名を引き継ぐ。支店名・口座番号は未設定で追加。口座ID、取引参照、残高、基準日、認証テーブルは維持する。旧nameの常設API互換処理は設けない。

## 検証

WindowsのNode.jsとVPS上の隔離Linuxコンテナで、それぞれ71件成功（既存65件＋追加6件）。実行するテストデータは合成データだけを使用。

| 確認対象 | 結果 |
|---|---|
| 登録・編集 | 銀行名・支店名・種別・口座番号を独立保存し、編集結果を再取得できる |
| 必須・型チェック | 空の銀行名、数値型の口座番号、廃止したnameによる保存を拒否 |
| 先頭0 | `0012345`を保存、`0009876`等へ編集しても先頭0を維持 |
| SQLite永続化 | 再接続後も文字列型・保存値・残高・基準日を維持 |
| 画面操作 | 実ブラウザーで登録、一覧、編集、再表示、日繰りの新しい口座見出しを確認 |
| API | 認証済みHTTP経由の登録・編集・取得でbranch/accountNumberを確認。nameは返さない |
| 関連画面・Excel | 売掛／買掛／入出金／固定支出／日繰りの選択肢・表見出し・Excel見出しが銀行名＋支店名 |
| 残高・決済 | 既存の月またぎ残高・分割決済・重複防止・更新競合等の回帰試験が成功 |
| 新形式バックアップ | 新項目・口座番号・取引の口座ID参照が復元後も一致 |
| 旧形式からの復元 | v1のバックアップから空の復元先へv2移行。元ファイルは無変更、ID・残高・基準日・認証レコードを保持 |

## VPSでの更新・復元確認

1. 資金繰り専用backupを一時停止し、旧版のSQLite Backup APIで更新前の整合バックアップを取得。
2. 新版の隔離コンテナでそのバックアップを復元・移行し、件数、集計、口座ID、残高、基準日、管理者件数の維持を確認。
3. 資金繰りapp・backupだけを0.3.0へ更新。
4. 新版での自動バックアップ成功を確認し、その実バックアップから一時DBへ復元。整合検査、外部キー検査、台帳検査、アプリ起動、ログイン画面、未認証APIの401、元バックアップ無変更を確認。

更新前退避先：`/var/backups/wfs/cashflow/pre-schema-v2-20260925`

更新前バックアップ：`cashflow-20260924T152611781Z-db7a3ec1`（日本時間9月25日00:26）。

更新後・復元確認済みバックアップ：`cashflow-20260924T152627046Z-16567855`、本体131,072 bytes。

管理者1名・既存口座1件を保持。実口座番号・業務本文・パスワードを調査出力やテストへ転記していない。本番DBへ合成データは投入していない。

旧イメージ0.2.0と旧ソースの退避も保持。v2 DBに旧アプリを直接接続しない。戻す場合は必要な変更を確認したうえで、資金繰り専用サービスを止め、更新前のバックアップを別領域へ復元する。

## 他サービス

n8n、PostgreSQL、Caddy、受注／利益管理は、作業前後のコンテナID・起動時刻が一致。CaddyfileのSHA-256も一致。これらのサービス／DB／設定への変更は行っていない。公開範囲も127.0.0.1:3310のまま維持。

画面を再読み込みすると新版を利用できる。公開用ドメインやCaddyの変更、Google Driveバックアップは今回の対象外。
